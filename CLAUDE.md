# Intent — инструкция для нового чата

Intent — продукт, который начинается с намерения человека. Главный экран — ИИ-чат, который понимает приказы и утверждения и сам создаёт задачи и напоминания. Есть ручной ежедневник и запросы знакомым с подтверждением и историей. После беты — открытый рынок намерений («куплю ↔ продам»), это основа монетизации. Сейчас бета до 100 пользователей (PWA + API), и код ещё устроен по-старому: главный экран — ежедневник. Владелец общается по-русски; отвечать и писать документацию по-русски.

## С чего начинать

1. Прочитать [docs/STATUS.md](docs/STATUS.md): текущее состояние и очередь задач.
2. По необходимости:
   - [docs/VISION.md](docs/VISION.md) — идея и границы продукта;
   - [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — устройство кода;
   - [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) — запуск, проверки, публикация.

## Правила работы

- **В конце каждой задачи обновлять документацию:**
  - `docs/STATUS.md` — состояние и очередь задач;
  - `docs/CHANGELOG.md` — новая запись сверху: что сделано, чем проверено, что не проверено;
  - `docs/ARCHITECTURE.md` — если изменились структура, API или модель данных.
- Перед сдачей работы прогнать проверки:
  - `server/`: `../.venv/Scripts/python.exe -m pytest -q -p no:cacheprovider`;
  - `web/`: `npm test` и `npm run build`.

  Если что-то не проверено (телефон, облако, push), так и писать.
- Корень проекта — **не git**. Git-клон GitHub лежит в `.local/deploy-repo`. Коммитить и пушить только по явной просьбе, порядок описан в DEVELOPMENT.md.
- `.local/` содержит личные данные владельца: пароль, снимки таблиц, бэкапы. Не публиковать, не удалять и не выводить пароли.
- Не запускать `npm ci` при работающем `vite preview` или dev-сервере: заблокированный `esbuild.exe` ломает установку посередине.
- Схему БД менять осторожно: миграций нет, `create_all` не добавляет колонки в существующие таблицы.
- API должен работать в одном процессе: rate limit, очередь ИИ и push-цикл живут в памяти.

## Кратко о стеке

- `web/`: React 19, TypeScript, Vite, vite-plugin-pwa, Vitest. Точка входа — `src/DiaryApp.tsx`.
- `server/`: FastAPI, SQLAlchemy, Pydantic. Локально SQLite (`server/intent.db`), в облаке PostgreSQL.
- Весь ежедневник пользователя — один JSON в `planner_states` с оптимистичной версией.
- ИИ: Groq (`openai/gpt-oss-120b`, OpenAI-совместимый API), если задан `GROQ_API_KEY` (локально — `.local/groq.env`), иначе Ollama + Qwen3 4B. Пока только черновики с подтверждением. Точность проверяет `scripts/check_assistant.py`. Ключ не выводить и не публиковать.
- Push: Web Push с VAPID.
- Хостинг: Render + Neon (`render.yaml`) или своя VM с `compose.yaml`.
