# Запуск на Render + Neon

## Бета без сна сервера

Проверено 03.10.2026 по [условиям Render Free](https://render.com/docs/free):
Free засыпает после 15 минут простоя, пробуждение занимает примерно минуту.
Отключить это настройкой FastAPI нельзя. Платный compute-план сервиса снимает
ограничения Free; платный план рабочего пространства сам по себе этого не делает.

Подготовлен `render.beta.yaml` с compute `starter`. Это отдельный вариант для
применения после согласования текущей цены в [Render](https://render.com/pricing).
Для уже работающего сервиса измените его compute plan в Dashboard, сохранив
DATABASE_URL и ключи VAPID. Файл сам по себе не изменяет тариф и не оплачивает его.
Основной `render.yaml` сохранён бесплатным, чтобы обновление кода не включало расходы.

Для минимальных расходов можно оставить Free и принять задержки: ранее загруженный
ежедневник открывается из IndexedDB, а после восстановления сервера синхронизируется.
Первое открытие сайта на новом устройстве всё равно зависит от сервера.
Искусственные пинги не заменяют надёжность постоянно работающего сервиса.

Ollama / Qwen3 4B не помещается в небольшой API-инстанс: оставьте существующую
отдельную машину с Ollama и задайте OLLAMA_URL через защищённую сеть. Не публикуйте
неавторизованный порт Ollama в интернет. Без этой машины работают ручное создание
и строго ограниченные простые команды; сложные запросы покажут недоступность ИИ.
Альтернатива в текущем стеке — существующий Docker Compose на постоянно работающей
VM; включение модели: `docker compose --profile setup run --rm model-pull`, затем
`docker compose --profile ai up -d`. Размер VM и расходы зависят от машины и нагрузки,
100 аккаунтов не означают 100 параллельных запросов модели.

После переключения проверьте `/api/health` после 20 минут без пользовательских
запросов, реальную доставку push при закрытом приложении, восстановление резервной
копии PostgreSQL и запрос к модели. Эти облачные проверки ещё не выполнены.

## Бесплатный запуск

Сайт и API запускаются одним Docker-сервисом, PostgreSQL хранится в Neon.
Тариф Render Free засыпает после 15 минут без запросов. Первый запрос
после простоя может ждать около минуты. Фоновая отправка напоминаний во время
сна не работает: этот вариант подходит для бесплатного знакомства с приложением,
но не для своевременных уведомлений. Для них используйте платный сервис без сна.
Также учитывайте бесплатные лимиты Neon и нагрузку фоновой проверки напоминаний.

1. Войдите в https://console.neon.tech через GitHub. Создайте проект Free,
   желательно во Frankfurt. Скопируйте строку подключения из Connect.
2. Замените только начало `postgresql://` на `postgresql+psycopg://`.
   Сохраните параметры SSL и остальную строку без изменений.
3. Откройте https://dashboard.render.com/select-repo?type=blueprint,
   подключите репозиторий `OmarTole/Intent`, ветку `main`.
4. Render прочитает `render.yaml`. Укажите подготовленную строку в
   секретной переменной `DATABASE_URL`. Убедитесь, что выбран план Free.
   Не записывайте строку подключения в GitHub или переписку.
5. Запустите создание сервиса. После успешной сборки откройте выданный
   HTTPS-адрес `https://…onrender.com`. `/api/health` должен отвечать успешно.
6. Зарегистрируйте аккаунт. База облака изначально пустая: локальные записи
   и права администратора сами не переносятся. Не удаляйте локальную базу.

Для уведомлений дополнительно задайте в Render Environment постоянные
`VAPID_PRIVATE_KEY`, `VAPID_PUBLIC_KEY`, `VAPID_SUBJECT` из приватного
локального файла `.local/push-config.json`. Затем разрешите уведомления
в приложении на новом HTTPS-адресе. Не генерируйте новые ключи при каждом деплое.

Права администратора назначаются командой `python -m app.manage make-admin EMAIL`
из каталога server с переменной окружения `DATABASE_URL`, указывающей на Neon.
Запускайте её в доверенной среде; на бесплатном Render веб-консоль может быть
недоступна. Пароль пользователя этим не изменяется.

Docker-сборка включает только код сервера и публичные файлы PWA. Пароли,
локальные базы и `.local` исключены из контекста сборки.
