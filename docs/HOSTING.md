# Публикация Intent: GitHub + сервер

GitHub хранит исходники. Для регистрации, синхронизации, базы данных и фоновых напоминаний нужен сервер. GitHub Pages эту серверную часть не запускает.

## Что нужно создать

1. Аккаунт [Oracle Cloud Always Free](https://www.oracle.com/cloud/free/). Регистрацию и проверку карты выполняет владелец аккаунта.
2. Виртуальную машину Ubuntu в домашнем регионе, в пределах Always Free. Проверяйте актуальные лимиты в консоли: [официальные условия](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm). Для A1 на момент подготовки инструкции — суммарно 2 OCPU и 12 ГБ памяти. Свободные мощности не гарантированы; малоиспользуемые машины могут быть отозваны.
3. Публичный IP и DNS-имя, указывающее на него. Можно использовать собственный домен или бесплатный поддомен [DuckDNS](https://www.duckdns.org/).
4. В сетевых правилах Oracle и системе разрешить входящие TCP 80/443, SSH 22 ограничить своим IP. Порты PostgreSQL и API наружу не открывать.

## Первый запуск на Ubuntu

Установите Docker Engine с Compose по [официальной инструкции](https://docs.docker.com/engine/install/ubuntu/). Команды ниже предполагают доступ к Docker у текущего пользователя.

```bash
git clone https://github.com/OmarTole/Intent.git
cd Intent
sudo apt-get update
sudo apt-get install -y python3-venv
python3 -m venv .venv
.venv/bin/pip install -r server/requirements.lock
.venv/bin/python scripts/setup_production.py --domain YOUR_DOMAIN --email YOUR_EMAIL
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

Замените `YOUR_DOMAIN` на реальное DNS-имя без `https://`, `YOUR_EMAIL` — на контактную почту. Скрипт создаст пароль базы и VAPID-ключи в `.env`, с правами 600. Повторный запуск не перезаписывает существующие ключи. Не публикуйте `.env` и не меняйте пароль после создания базы без отдельной процедуры смены пароля PostgreSQL.

По умолчанию запускаются только Caddy, FastAPI и PostgreSQL. Ollama вынесен в необязательный профиль `ai` и ежедневнику не требуется. Данные PostgreSQL и сертификаты Caddy хранятся в Docker volumes.

## Первый администратор

Откройте `https://YOUR_DOMAIN`, зарегистрируйтесь по почте и паролю, затем на сервере выполните:

```bash
docker compose exec api python -m app.manage make-admin YOUR_EMAIL
```

После назначения роли выйдите и войдите снова. Новые регистрации не получают административные права автоматически.

## Перенос личных данных

В GitHub нет локальной базы, `.local`, паролей, исходных Google-таблиц или резервных копий. Новый сервер запускается с пустой базой. Перенос существующего аккаунта и результатов выполняется отдельно через защищённое соединение после создания сервера; обычная регистрация не переносит локальные данные автоматически. До переноса сохраните локальную базу и резервную копию из настроек ежедневника. Не удаляйте локальную установку.

## Проверка после запуска

- `curl --fail https://YOUR_DOMAIN/api/health` возвращает `status: ok`.
- Регистрация и вход работают; задача сохраняется и видна после перезагрузки.
- Большой ежедневник сохраняется: для `/api/planner` установлен лимит 4 000 000 байт, для остальных API — 32 КБ.
- На телефоне установите PWA, разрешите уведомления и проверьте тестовое напоминание. HTTPS и работающий сервер необходимы для доставки.
- Админка доступна только назначенному администратору.

## Обновления и резервная копия

```bash
sh scripts/backup.sh
git pull --ff-only
docker compose up -d --build
```

Копируйте резервные копии с сервера в отдельное защищённое место. `docker compose down -v` удаляет volumes с данными — не используйте эту команду для обычного обновления.

Docker-сборка и выдача сертификата должны быть проверены на реальном сервере. Наличие файлов в GitHub не означает, что сайт уже опубликован.
